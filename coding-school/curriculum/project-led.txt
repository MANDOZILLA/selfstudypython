PROJECT-LED APCSP → MACHINE LEARNING → RESEARCH CURRICULUM

Assumption:
- 75–90 minutes per day
- 5–6 days per week
- Start: APCSP-level Python
- Goal: by winter, have a legitimate ML project to show
- Goal: by spring/summer, be capable of contributing meaningfully to an applied ML research project

CORE DESIGN RULE

Projects are not rewards after lessons.
Projects are the environment in which lessons happen.

A new concept should usually appear because the current project creates a problem that the learner cannot solve cleanly with existing tools.

Examples:
- “I need this action to repeat until something changes.” → while loops
- “I duplicated this logic six times.” → functions
- “I need to store structured records.” → dictionaries
- “I have 50,000 values and Python loops are clumsy.” → NumPy
- “I need to analyze labeled columns and missing values.” → Pandas
- “My model works on training data but fails on new data.” → overfitting/generalization
- “My accuracy looks impossibly good.” → data leakage

The curriculum should usually introduce only 1–3 genuinely new ideas at a time.

Everything else in the project should reuse older skills.


==================================================
1. LEARNING MODEL
==================================================

Every concept gets a complexity level.

LOW COMPLEXITY
Examples:
- enumerate
- zip
- tuples
- simple slicing
- basic comprehensions
- simple plotting options

Learning structure:
1. Short explanation
2. Two complete examples
3. One replication task
4. One transfer task
5. Immediate use in the active project

Time:
About 20–45 minutes total.

MEDIUM COMPLEXITY
Examples:
- dictionaries
- exceptions
- NumPy indexing
- Pandas groupby
- train/test splitting
- scaling
- imputation

Learning structure:
1. Conceptual explanation
2. Several examples
3. 3–5 increasingly difficult tasks
4. Debugging task
5. Small applied build
6. Reuse the next day
7. Retrieval later

Time:
About 1–3 sessions.

HIGH COMPLEXITY
Examples:
- functions
- OOP
- vectorization
- probability
- linear regression
- overfitting
- gradient descent
- neural networks

Learning structure:
1. Mental model
2. Multiple worked examples
3. Guided implementation
4. Harder implementation with less starter code
5. Debugging
6. Mini-project
7. Use inside anchor project
8. Reuse the next day
9. Transfer days/weeks later
10. Explain in your own words

Time:
Usually 3–8 sessions.

Mastery is not:
“I completed the lesson.”

Mastery means:
- independent transfer
- later retrieval
- ability to explain the idea
- ability to choose the idea without being told to use it


==================================================
2. WEEKLY STRUCTURE
==================================================

Typical six-session week:

Session 1
- retrieval from older material
- introduce 1–2 new concepts
- worked examples
- first project feature using the concept

Session 2
- same concept in harder context
- less starter code
- project feature

Session 3
- add 1 related concept
- combine it with the previous concept
- project feature

Session 4
- mini-project or substantial feature
- no step-by-step recipe

Session 5
- debugging
- transfer problem
- explanation/reflection

Session 6
- anchor-project development
- old-skill retrieval
- documentation / tests / cleanup

Sunday:
- off or catch-up

Recommended daily split:
- 10 min retrieval
- 15–20 min teaching/examples
- 40–50 min building
- 10 min debugging/testing
- 5 min reflection

Approximate learning ratio:
- 60–70% project building
- 20–30% direct teaching/examples
- 10% retrieval/debugging

- only dictionaries count

==================================================
17. FINAL STANDARD
==================================================

The end goal is not:

“I know NumPy.”
“I know Pandas.”
“I know PyTorch.”

The end goal is:

“I can take a real question, find or clean data, formulate a hypothesis, build a reproducible experiment, train appropriate models, evaluate them correctly, detect leakage and overfitting, analyze failures, explain uncertainty, and communicate the result.”

That is the level that starts becoming useful for:
- ML internships
- startup work
- research with a professor
- serious college-portfolio projects

The curriculum should therefore optimize for:
1. independent problem solving
2. experimental thinking
3. reproducibility
4. transfer between projects
5. depth on important concepts
6. reaching real ML early enough to build something meaningful by winter
